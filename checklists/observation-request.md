# 관찰 요청 대본

브라우저를 띄울 수 없는 자리에서 완료를 판정하는 절차다. 관찰하는 눈이 사용자이므로, **무엇을 눌러 무엇이 보여야 하는지**를 이쪽이 먼저 적어 준다. "확인해 보세요" 라고만 적으면 관찰이 아니라 떠넘기기다.

## 규칙

- 예상 결과를 먼저 적는다. 사용자가 판정만 하면 되게 한다.
- 쪽마다 적는다. 등급 0 정지 쪽도 넘침과 여백은 본다.
- 어긋난 항목은 고친 뒤 그 항목만 다시 확인받는다. 전체를 다시 보게 하지 않는다.
- 게이트를 못 돌렸다는 사실을 함께 밝힌다. 못 돌린 것과 통과한 것을 같은 말로 적지 않는다.

## 먼저 부탁하는 것

1. 파일을 브라우저로 연다 (더블클릭 또는 `file://` 주소).
2. 창을 최대화한다. 가능하면 발표에 쓸 화면과 같은 비율로 본다.
3. `F11` 로 전체화면에 들어간다.

## 전 쪽 공통

- 네 변에 여백이 고르게 남아 있는가. 글자나 상자가 화면 끝에 닿거나 잘리지 않는가
- 좌우 키로 처음부터 끝까지 넘어가는가. 마우스가 필요한 자리가 있는가
- 창 너비를 좁혔다 넓혔다 할 때 무너지는 쪽이 있는가
- 자동으로 꺾인 줄이 있는가 (원고가 정한 자리가 아닌 곳에서 줄이 넘어간 곳)

## 쪽별 (등급 2~3 쪽마다 아래 형식으로 적는다)

```markdown
### N쪽 · <쪽 제목>

- 이 쪽에서 보여 주려는 것: <핵심 메시지 한 줄>
- `Space` 를 <n>번 누른다
  - 1번째: <무엇이 일어나야 하는가>
  - 2번째: <무엇이 일어나야 하는가>
  - 마지막: 아래 맺음 문장 "<문장>" 이 켜진다
- <요소>에 마우스를 올린다 → <무엇이 미리 보여야 하는가>
- <요소>를 누른다 → <무엇이 고정되어야 하는가>
- 빈 곳을 누른다 → 고정이 풀린다
- `End` 를 누른다 → 한 번에 완료 상태가 된다
- 완료 상태에서 `Space` → 처음 상태로 돌아간다
- 조작 뒤 바로 오른쪽 키 → 다음 쪽으로 넘어간다 (키보드가 즉시 듣는가)
- 이 쪽을 떠났다 돌아온다 → 처음 상태다
```

## 받은 답을 처리하는 법

- 전건 확인이면 9단계 조작 관찰 통과로 기록한다. 무엇을 확인받았는지 함께 적는다.
- 어긋난 항목이 있으면 **원인을 그 쪽의 명세와 대조**한다. 명세대로인데 어긋나 보이면 명세가 틀린 것이고, 명세와 다르면 구현이 틀린 것이다. 둘을 구분해 고친다.
- 사용자가 "이상하다" 고만 적은 항목은 무엇이 어떻게 이상한지 되묻는다. 추측으로 고치지 않는다.
