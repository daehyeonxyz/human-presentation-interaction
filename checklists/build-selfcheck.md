# 구현 자가 점검표

8단계 구현을 마친 뒤 코드와 대조한다. 전 항목 통과가 8단계의 통과 기준이다. 이 표는 관찰을 대신하지 못한다. 관찰 앞에서 걸러 내는 그물이다.

항목마다 **어떻게 확인하는가**가 붙어 있다. 눈으로 훑어 "그럴 것이다" 로 통과시키지 않는다.

## 무대 계약

- [ ] 배율이 `min(vw/1920, vh/1080)` 이고 설계 폭이 `clamp(1920, vw/s, 2560)` 이다 — `fit()` 의 식을 그대로 읽어 대조한다
- [ ] 설계 높이가 1080 고정이다 — 세로를 가변으로 두면 같은 판이 화면비마다 다른 밀도를 요구한다
- [ ] 레터박스를 감추지 않고 그 쪽의 캔버스 색으로 둔다 — `.viewport` 배경이 쪽 캔버스를 따라간다
- [ ] 네 변 여백이 정확히 80 이다 — `.frame` 의 `left/top/width/height` 가 `--margin` 으로만 계산된다
- [ ] 본체 행이 `1fr` 이라 아래가 남지 않는다 — `grid-template-rows` 에 `1fr` 이 있다
- [ ] `transform` 이 스테이지 배율과 `object-continuity` 의 위치 이어받기에만 쓰인다 — `transform:` 을 전수 검색해 확인하고, 이어받기에 쓴 자리는 어느 물건이 어느 쪽에서 어느 쪽으로 이어지는지 적혀 있다

## 키보드 계약

- [ ] 좌우 키가 쪽 넘김이다
- [ ] `Space` 가 그 쪽의 다음 조작 하나다. 두 현상이 한 번에 일어나지 않는다
- [ ] `End` 가 그 쪽의 완료 상태다
- [ ] 완료된 쪽에서 `Space` 가 처음 상태로 되돌린다
- [ ] 조작 뒤 초점이 풀려 방향키가 즉시 듣는다 — 모든 조작 핸들러 끝에 `release()` 가 있다
- [ ] `Enter` 로도 초점이 놓인 조작이 실행된다
- [ ] 처음부터 끝까지 마우스 없이 진행된다 — 마우스로만 닿는 조작이 하나도 없다

## 공용 API (게이트가 전제한다)

- [ ] 쪽이 `.slide` 이고 `window.go(n)` 이 0 기반이다
- [ ] `window.still()` 이 등장 애니메이션을 정지시킨다
- [ ] 조작이 있는 쪽이 `PAGE[쪽번호]` 에 `step`·`finish`·`reset` 을 등록했다

## 안정성 가드레일

`interaction-grammar.md` 의 열일곱 가지를 전 쪽에 적용한다.

- [ ] **칸 예약** — 나중에 켜지는 것의 칸이 정지 상태에도 잡혀 있다. 켜질 때 위의 것이 밀리지 않는다
- [ ] **늘어나는 방향** — 늘어나는 요소의 방향이 고정이고 그 방향에 여유가 있다
- [ ] **위치 이동 금지** — 등장은 투명도로만 한다. 위치는 처음부터 끝까지 그대로다
- [ ] **넘침 제어** — 타일에 `overflow: hidden` 과 `min-width: 0` 이 있다. 긴 글자가 칸을 밀지 않는다
- [ ] **이동 경로** — 다른 칸으로 이동하는 요소의 경로 위 조상에 `overflow: hidden` 이 없다 — 이동이 있는 쪽마다 조상을 거슬러 올라가며 확인한다. 정지 캡처로는 안 잡힌다
- [ ] **내용 교체** — 같은 칸의 내용이 바뀔 때 빈 프레임이 없다 — 교체 지점을 전수로 세고 각각이 겹침 교차인지 확인한다
- [ ] **물건 연속** — 두 쪽에 함께 있는 물건이 같은 위치에서 이어진다 — 이어지는 물건 목록과 대조하고 두 쪽의 좌표를 재서 같은지 본다
- [ ] **박자 일치** — 쪽마다 Space 수가 노트의 마디 수와 같다 — 노트와 `data-steps` 를 쪽마다 대조한다
- [ ] **재실행 방지** — 한 번만 일어나야 하는 애니메이션이 다음 단계에서 다시 돌지 않는다 — 단계 훅이 마지막 단계 이후에도 불리는지 확인한다
- [ ] **진입 상태** — 고르는 판이 진입 시 첫 항목을 골라 두었다
- [ ] **속도 일치** — 켜짐과 내용 교체와 위치 이동이 각각 토큰 하나씩만 쓴다 — `transition` 과 `animate` 의 시간 값을 전수로 세어 종류가 셋을 넘지 않는지 본다
- [ ] **이동과 페이드** — 이동에 걸린 불투명도가 뒤쪽 구간에만 있다 — 이동 첫 프레임에서 요소가 보이는지 중간 캡처로 확인한다
- [ ] **상태 색** — 같은 개념이 발표 전체에서 같은 색이고, 한 단계에서 강조색을 받은 것이 다음 단계에서 돌아온다
- [ ] **호버 반응** — 커서가 `pointer` 인 요소가 전부 호버에 반응한다. 반응 없는 `pointer` 가 하나도 없다
- [ ] **정적 폴백** — 인터랙션이 실패해도 보여 줄 정적 상태가 있다
- [ ] **쪽 되돌림** — 쪽을 떠나면 그 쪽이 처음 상태로 돌아간다. 되돌아가는 장면은 보이지 않는다
- [ ] **되돌림 취소** — 다음 쪽에 갔다 곧바로 돌아와도 화면이 초기화되지 않는다 — 지연 되돌림을 쓰는 덱은 쪽 활성화에서 그 예약을 취소하는지 코드로 확인한다
- [ ] **순서의 사실성** — 단계가 그리는 순서가 공식 문서의 서술과 같다 — 순서를 주장하는 쪽을 목록으로 뽑고 각각을 원문과 대조한다
- [ ] **겹침 규율** — `z-index` 가 정해진 층에서만 쓰인다
- [ ] **키보드 복구** — 위 키보드 계약 항목과 같다
- [ ] **자기완결** — 서체와 이미지가 base64 로 인라인돼 있다. `src=` 와 `url()` 전수가 `data:` 로 시작한다

## 원고와 화면

- [ ] 화면의 글자가 원고와 한 글자도 다르지 않다 — 원고와 HTML 을 나란히 놓고 쪽마다 대조한다
- [ ] 줄바꿈이 원고가 정한 위치에서만 일어난다. 화면 폭 때문에 꺾인 줄이 없다
- [ ] 발표자가 말할 문장이 화면에 인쇄돼 있지 않다 — 노트의 문장과 화면의 문장이 겹치는 쪽을 찾는다
- [ ] 화면 구석에 붙은 해설 두 줄이 없다. 있으면 그 화면이 메시지를 전달하지 못한 것이다
- [ ] 제품 사양(모델 이름·버전·가격·한도)이 공식 문서와 같고, 그 조직이 실제로 쓰는 버전으로 확인받았다
- [ ] 구현하며 발명한 이름이나 문장이 없다 — 원고에 없는 명사가 화면에 있으면 그것이 발명이다
- [ ] 수치와 예시에 예시 표기가 있다
- [ ] 출처가 필요한 주장에 출처가 화면에 있다
- [ ] 노트의 Space 위치가 실제 단계와 같다 — 화면을 고친 쪽은 노트도 함께 고쳐졌다
- [ ] 앞서 받은 지적이 되돌아간 곳이 없다 — 지적 목록을 열어 항목마다 현재 화면과 대조한다

## 시각과 제품 재현

- [ ] 모든 면이 배경과 구분된다 — 캔버스와 같은 계열의 옅은 면이 없다
- [ ] 같은 제품 화면이 쪽마다 같은 폭과 모서리와 글자 크기다 — 그 화면이 나오는 쪽 전수의 규격을 재서 대조한다
- [ ] 재현 안에 발표 액센트 색이 칠해져 있지 않다
- [ ] 재현 안의 목록과 파일 이름이 사용자 확인을 거쳤다
- [ ] 본체를 다 쓰지 않는 쪽이 세로 가운데에 서 있다
- [ ] 좌우 두 열이 같은 높이로 본체를 다 쓴다
- [ ] 제목이 두 줄로 꺾인 쪽이 없다
- [ ] 쪽 번호가 오른쪽 아래에 숫자만 있다
- [ ] 이어지는 쪽의 머리 높이가 같다 — 한쪽만 부제가 빠진 쪽이 없다

## 코드 위생

- [ ] 쓰이지 않는 CSS 규칙이 없다 — 선택자 전수를 DOM 과 대조해 한 번도 맞지 않는 것을 센다
- [ ] 불려지지 않는 함수가 없다
- [ ] 색과 크기가 토큰으로만 들어간다 — 값을 직접 적은 곳을 전수 검색해 확인한다. 제품 재현 안의 제품 값은 예외이고 그 예외를 주석으로 밝힌다

## 명세 이행

페이지 명세를 한 줄씩 짚으며 대조한다.

- [ ] 상태 — 항상 보이는 전역 상태가 명세가 정한 칸에 있다
- [ ] 시퀀스 — 단계 수와 각 단계에서 일어나는 일이 명세와 같다
- [ ] 상세 — 호버 미리보기와 클릭 고정이 짝으로 있다
- [ ] 해석 — 체험 뒤 takeaway 문장이 화면에 있다
- [ ] 폴백 — 명세가 정한 정적 상태가 실제로 구현돼 있다
- [ ] 판 — 대비를 이루는 두 쪽이 같은 판을 쓰고 바뀌는 칸만 다르다
- [ ] 등급 — 구현된 것이 명세의 등급과 같다. 구현하다 등급이 올라갔으면 명세를 고치는 것이 아니라 왜 올랐는지 따진다
