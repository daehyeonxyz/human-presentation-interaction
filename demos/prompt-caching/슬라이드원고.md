# 프롬프트 캐싱과 비용 — 슬라이드 원고

인쇄 층의 단일 원본이다. 구현은 이 글자를 앉히기만 하고 새 문장을 만들지 않는다. 강조 낱말은 굵게 표시한다. 2026-08-28 반려로 전면 개정했다. 맺음은 경구가 아니라 화면의 구체 수치와 사실로 닫고, 조작 없는 쪽에는 맺음을 두지 않는다. 제목은 report 결의 압축 명사구다 (2026-08-28 사용자 교정).

## 1쪽 표지 (cover-stage)

- 제목: 프롬프트 캐싱과
  비용 (두 줄. 줄 나눔은 이 표기가 정본이다)
- 태그라인: 같은 앞부분을 다시 보내지 않는 법
- 오른쪽 위 영문: PROMPT CACHING
- 오른쪽 아래 영문: human-presentation-interaction demo deck 02

## 2쪽 (등급 0 정지, 세 항목 전부 펼쳐서 표시)

- kicker: COST
- 제목: 토큰 비용의 **구조**
- 부제: Input · Output · Repetition
- 항목 1 이름: 입력 토큰
- 항목 1 본문: 시스템 프롬프트와 도구 정의와 지난 대화 전부가
  요청마다 입력으로 다시 들어간다
- 항목 2 이름: 출력 토큰
- 항목 2 본문: 모델이 새로 만든 글자
  단가가 입력보다 높다
- 항목 3 이름: 반복 전송
- 항목 3 본문: 대화가 길어질수록 같은 앞부분을
  다시 보내는 비중이 커진다
  캐싱이 줄이는 것이 이 부분이다
- 맺음: 없음

## 3쪽 (drag-compare, 등급 2)

- kicker: CACHE
- 제목: 캐시가 저장하는 **범위**
- 부제: Without cache · With cache
- 왼쪽 화면 이름: 캐시 있음
- 오른쪽 화면 이름: 캐시 없음
- 공통 구간 라벨: 시스템 프롬프트 / 도구 정의 / 지난 대화 / 새 질문
- 캐시 없음 쪽 구간 표기: 전부 입력 단가 (예시 100%)
- 캐시 있음 쪽 구간 표기: 저장된 앞부분은 캐시 단가 (예시 10%) 새 질문만 입력 단가
- 맺음: 경계를 끝까지 밀어 보면 남는 차이는 새 질문 한 줄이다

## 4쪽 (input-sandbox, 등급 3)

- kicker: HIT
- 제목: 적중 조건, **같은 접두사**
- 부제: Prefix match
- 입력 칸에 차오를 요청 후보 (전송 버튼으로 차례대로 재현):
  - 요청 1: 어제 회의록을 요약해 줘
  - 요청 2: 요약에서 결정 사항만 뽑아 줘
  - 요청 3: (시스템 프롬프트를 바꾼 뒤) 결정 사항을 표로 만들어 줘
- 관찰 창 머리: 요청의 구성
- 관찰 창 구간 라벨: 캐시 적중 / 새로 계산
- 관찰 창 해설 1 (두 줄): 첫 요청. 저장된 것이 없어 전부 새로 계산
  이 요청의 앞부분이 캐시에 저장된다
- 관찰 창 해설 2 (두 줄): 앞부분이 같아 적중. 새 질문만 계산
  입력 대부분이 캐시 단가로 내려간다
- 관찰 창 해설 3 (두 줄): 앞부분이 바뀌어 적중 실패. 전부 새로 계산
  바뀐 접두사가 새로 저장된다
- 맺음: 요청 2 는 앞이 같아 적중했고 요청 3 은 시스템 프롬프트가 바뀌어 전부 새로 계산했다

## 5쪽 (drag-threshold, 등급 2)

- kicker: RATE
- 제목: **적중률**과 입력 비용
- 부제: Hit rate · Input cost
- 슬라이더 이름: 캐시 적중률
- 게이지 이름: 하루 입력 비용 (예시)
- 기준 표기: 적중 0%면 100 / 적중 100%면 대략 10 (예시)
- 곁 열 머리: 접두사를 안정시키는 방법
- 곁 열 항목 (세 줄):
  - 시스템 프롬프트와 도구 정의를 앞에 고정한다
  - 날짜와 세션 값처럼 자주 바뀌는 것을 뒤로 보낸다
  - 대화 이력은 그대로 두고 끝에만 덧붙인다
- 곁 문장: 자주 바뀌는 것을 요청의 뒤로 보내면
  접두사가 안정되어 적중률이 오른다
- 맺음: 적중률 60%면 하루 입력 비용이 100 에서 46 으로 내려간다 (예시)

## 6쪽 정리 (accumulate-recap)

- kicker: RECAP
- 되짚기 항목 (이름과 부연 한 줄):
  - 반복 전송: 같은 앞부분이 요청마다 다시 나간다
  - 남는 차이는 새 질문 한 줄: 겹침 비교에서 이음매가 없던 줄
  - 글자 그대로 같은 접두사: 한 글자가 달라도 적중이 깨진다
  - 100 에서 46: 적중률 60% 의 하루 입력 비용 (예시)
- 선언: 같은 접두사를 유지하는 요청 구조가 입력 비용을 줄인다
- 다음 물음: 우리 요청에서 매번 다시 보내는 앞부분은 몇 토큰일까
