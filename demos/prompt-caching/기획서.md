# 프롬프트 캐싱과 비용 — 기획서

## 기획

- 목적: 검증 덱 2호다. 택소노미에서 규격만 있고 실물이 없는 세 판(drag-compare, drag-threshold, input-sandbox)을 실전 제작으로 검증한다.
- 청중: LLM API 를 쓰는 개발자. 세미나 결이라 인쇄 층은 명사형 종결과 반말 평서를 쓴다.
- 결론 한 줄: 같은 접두사를 다시 보내는 구조를 만들면 캐시가 입력 비용을 대부분 지운다.
- 발표 시간: 데모용 6쪽. 시간 게이트는 적용하지 않는다.

## 구성 (판 지도와 셀 지도)

레이아웃 패턴은 원본 택소노미(`~/.claude/skills/layout-taxonomy/taxonomy.md`)의 ID 로 지목한다. 조작 문법은 `조작문법.md` 의 `g-*` 다.

| 쪽 | 핵심 메시지 | 레이아웃 패턴 | 조작 문법 | 등급 | 근거 |
|---|---|---|---|---|---|
| 1 | 표지 | `oversized-type` + `swiss-grid` | `g-none` | 0 | 조작 없음 |
| 2 | 비용은 세 곳에서 쌓인다 | `hierarchical-grid` + `modular-grid` | `g-none` | 0 | 세 항목은 정지 화면으로 증명된다. 클릭 공개는 논증에 기여하지 않아 강등했다 |
| 3 | 캐시는 요청의 앞부분을 저장한다 | `bento-grid` + `split-screen` | `g-drag` · `g-pin` | 2 | 캐시 유무의 대비를 한 화면에서 겹쳐 봐야 한다 |
| 4 | 같은 접두사로 보내야 적중한다 | `bento-grid` + `asymmetric-two-up` | `g-input` · `g-pin` | 3 | 요청을 직접 보내 보는 체험이 메시지다 |
| 5 | 적중률이 비용을 정한다 | `bento-grid` + `asymmetric-two-up` | `g-drag` · `g-pin` | 2 | 값을 끌면 비용이 바뀌는 관계 자체가 메시지다 |
| 6 | 정리 | `hierarchical-grid` + `oversized-type` | `g-advance` | 1 | 되짚기와 선언 |

### 셀 지도

프레임은 여백 80 안쪽의 12열 격자다. 면을 갖는 셀과 배경 위에 놓는 셀을 함께 적는다.

| 쪽 | 셀 | 면 |
|---|---|---|
| 1 | 머리 행 오른쪽 영문 / 본체 큰 제목 / 바닥 왼쪽 태그라인과 오른쪽 표기 | 전부 배경 위 |
| 2 | 1~4열 표제 · 5~12열 항목 셋 | 표제는 배경 위, 캐싱이 줄이는 셋째 항목만 흰 면, 나머지 둘은 우물 면 |
| 3 | 표제 행 전폭 · 전폭 장치(두 층 겹침 판 네 줄 · 경계 핸들 · 맺음) | 장치는 흰 면, 구간 줄은 단가에 따라 옅은 면과 짙은 면, 맺음은 그 안의 우물 면 |
| 4 | 표제 행 전폭 · 1~8열 조작 창(이력 · 입력 바 · 맺음) · 9~12열 관찰 창(머리 · 구성 막대 · 범례 둘 · 해설 두 줄) | 조작 창은 흰 면, 관찰 창은 우물 면, 범례는 그 안의 흰 면 |
| 5 | 표제 행 전폭 · 1~8열 장치(적중률 행 · 슬라이더 · 비용 게이지 · 기준 표기 · 맺음) · 9~12열 곁 열(머리와 항목 셋과 곁 문장) | 장치는 흰 면, 맺음은 그 안의 우물 면, 곁 열 항목은 우물 면이고 머리와 곁 문장은 배경 위 |
| 6 | 1~5열 선언과 다음 물음 · 6~12열 되짚기 넷(이름과 부연) | 선언과 다음 물음은 배경 위, 되짚기는 우물 면이고 켜지면 흰 면 |
## 채널 배분

- 말: 각 쪽의 배경 설명과 전환.
- 인터랙션: 3쪽 겹침 핸들, 4쪽 요청 전송 재현, 5쪽 적중률 슬라이더.
- 텍스트: 각 쪽의 주장 한 줄과 맺음 문장.

### 5쪽 곁 열 결정 (2026-08-28)

장치를 열두 칸으로 넓히고 곁 문장을 장치 안으로 넣는 안을 검토했다. 원고 증보로 곁 열이 머리와 항목 셋과 곁 문장을 갖게 되면서 오른쪽 네 칸이 실제 내용으로 찼으므로 여덟 칸과 네 칸의 나눔을 그대로 뒀다. 장치를 넓히면 그 내용이 갈 곳이 없어진다.

장치 안의 순서는 적중률 행 다음에 슬라이더가 오고 그 아래에 비용 게이지가 온다. 조작이 자기 값 바로 아래에 있고 결과가 그 아래로 이어져 원인과 결과가 세로로 읽힌다.

## 근거

- 수치는 전부 시뮬레이션 예시이고 화면에 (예시) 를 표기한다. 실제 단가를 주장하지 않는다.
- 개념 근거는 Anthropic API 문서의 prompt caching 동작이다.
