# 프롬프트 캐싱과 비용 — 인터랙션 명세

등급 2~3 쪽의 상태와 시퀀스 명세다. 조작 문법과 가드레일의 단일 원본은 레포 루트 `interaction-grammar.md` 이고 레이아웃 패턴은 `layout-taxonomy.md` 가 원본 택소노미로 지목한다.

2쪽은 등급 0 정지라 조작이 없다. 세 항목이 처음부터 다 펼쳐져 있고 맺음도 두지 않는다.

6쪽은 되짚기 넷이 하나씩 켜지고 다 켜지면 다음 물음이 붙는다. 선언은 처음부터 왼쪽에 보인다.

## 3쪽 drag-compare

- 핵심 메시지: 캐시는 요청의 앞부분을 저장한다.
- 등급과 근거: 2. 캐시 유무의 대비를 같은 자리에서 겹쳐 봐야 차이가 앞부분뿐이라는 것이 드러난다.
- 상태: 같은 요청 구조 그림 두 장이 겹쳐 있고 세로 핸들이 경계다. 정지 상태에서 핸들은 가운데에 있고 왼쪽은 캐시 있음 오른쪽은 캐시 없음이 보인다.
- 시퀀스: 없음. 이 판의 조작은 순서가 아니라 경계 탐색이다.
- 상세: 구간에 호버하면 그 구간의 단가 표기가 커진다. 클릭하면 고정된다.
- 해석: 핸들을 양 끝까지 오가면 맺음이 켜진다. 맺음은 장치의 마지막 행이고 정지 상태에도 자리가 잡혀 있다.
- 통제권: 핸들은 마우스 끌기와 좌우 화살표(핸들에 초점이 있을 때)로 움직인다. 초점을 잃으면 화살표는 즉시 쪽 넘김으로 돌아간다. Space 는 핸들을 가운데·왼끝·오른끝 순서로 옮긴다.
- 폴백: 핸들이 가운데에 있는 정지 상태 자체가 폴백이다.

## 4쪽 input-sandbox

- 핵심 메시지: 같은 접두사로 보내야 적중한다.
- 등급과 근거: 3. 요청을 보내고 적중이 갈리는 것을 관찰하는 체험 자체가 메시지다.
- 상태: 왼쪽 조작 창에 입력 칸과 전송 버튼과 요청 이력. 오른쪽 관찰 창에 요청 구성 막대와 해설 칸. 정지 상태에서 입력 칸에 요청 1이 이미 담겨 있다.
- 시퀀스: 전송을 누르면 입력 칸의 요청이 이력으로 올라가고 관찰 창 막대가 적중 구간과 새로 계산 구간으로 갈린다. 다음 요청이 입력 칸에 차오른다. 요청 3 전에는 시스템 프롬프트가 바뀌었다는 표시가 이력에 남는다.
- 상세: 이력 항목이나 막대 구간에 호버하면 해당 구성이 미리보기로 표시되고 클릭하면 고정된다.
- 해석: 세 요청을 다 보내면 맺음이 켜진다.
- 통제권: Space 가 전송과 같다. 입력 칸은 재현 전용이라 실제 타이핑을 받지 않는다.
- 폴백: 세 요청이 다 보내진 이력과 마지막 구성 막대가 보이는 상태.

## 5쪽 drag-threshold

- 핵심 메시지: 적중률이 비용을 정한다.
- 등급과 근거: 2. 값을 조절하면 결과가 바뀌는 관계 자체가 메시지다.
- 상태: 장치 안에 적중률 슬라이더와 비용 게이지와 눈금이 항상 보인다. 정지 상태에서 슬라이더는 0% 이고 게이지는 100 이다.
- 시퀀스: 없음. 슬라이더 값에 게이지가 즉시 따라온다.
- 상세: 게이지에 호버하면 지금 값의 계산 내역이 표시된다.
- 해석: 슬라이더가 60% 를 넘으면 맺음이 켜진다.
- 통제권: 슬라이더는 끌기와 좌우 화살표(초점이 있을 때)로 움직인다. Space 는 0, 60, 100 순서로 옮긴다.
- 폴백: 슬라이더 100% 와 그때의 게이지가 보이는 상태.

## 판 규격 검증 관찰 기록

세 판을 실물로 구현하면서 규격이 현실과 어긋난 곳을 여기에 적는다. 고친 내용은 레포 루트 `layout-taxonomy.md` 의 해당 절에 반영했다.

### drag-compare

- 정지 위치를 가운데가 아니라 62% 로 바꿨다. 위 명세는 가운데였고 택소노미는 한쪽 끝에서 조금 들어온 곳이었다. 택소노미를 따랐고 근거를 하나 더 찾았다. 핸들이 가운데에 있으면 지름 56 의 핸들이 두 층 항목의 중심점을 덮어 그 항목을 겨냥할 수 없다. 호버 전수 검사는 요소의 중심점에 마우스를 올리므로 항목 여덟 개가 통째로 검사에서 죽는다.
- Space 순서를 "가운데·왼끝·오른끝" 에서 "정지 위치·왼끝·오른끝" 으로 바꿨다. 정지 위치가 가운데가 아니므로 이름이 어긋난다.
- 겹침 공개를 `clip-path: inset(0 0 0 경계)` 로, 경계 이동을 `left` 로 구현했다. 이 판은 `no-position-shift` 의 예외가 아니다.
- 두 층의 같은 항목에 교차 표시를 걸었다. 한 층의 항목을 짚으면 다른 층의 같은 항목에도 링이 걸린다. 링이 경계를 가로질러 이어지고, 겨냥점이 아래층에 떨어져도 위층 표시가 함께 켜진다.
- 층 이름 배지를 판 위가 아니라 각 층 안에 넣었다. 판 위에 두면 그 층이 다 가려진 뒤에도 이름이 남는다.
- "구간에 호버하면 단가 표기가 커진다" 를 "단가 표기가 또렷해진다" 로 바꿨다. 글자 크기 변화는 `no-position-shift` 가 허용하는 속성이 아니다. 색과 링으로 낸다.
- 두 층에서 값이 같은 줄을 하나 뒀다. 새 질문 줄은 양쪽 다 입력 단가라 경계가 지나가도 이음매가 안 생긴다. 그 한 줄이 "차이는 앞부분뿐" 을 형태로 증명한다.

### input-sandbox

- 창 좌표를 (80, 240) 1160x584 에서 (80, 284) 1160x540 으로 바꿨다. 택소노미 표는 부제가 없는 경우를 못박아 두었는데 원고가 부제 Prefix match 를 준다. 원고가 인쇄 층의 단일 원본이므로 창을 무대 좌표에 맞췄다.
- 정지 상태를 "요청 1 이 입력 칸에 담겨 있음" 에서 "요청 1 을 이미 보낸 뒤" 로 바꿨다. 아무것도 안 보낸 화면은 조작 창이 빈 흰 판이고 관찰 창의 막대와 값과 해설이 모두 비어 어느 쪽이 무엇인지 형태로 안 갈린다. 첫 요청의 결과는 결론이 아니라 기준선이라 미리 보여도 결론을 앞당기지 않는다.
- 관찰 창의 겨냥 대상을 막대 구간에서 범례 행으로 옮겼다. 적중 구간은 요청 1 과 요청 3 에서 폭이 0 이라 겨냥 대상이 될 수 없다. 범례 행이 겨냥 대상이고 막대 구간은 그 응답이다.
- 막대 트랙 면과 적중 구간 색을 데이터 사다리에서 두 단 떼어 놓았다. 붙여 두면 빈 트랙이 꽉 찬 적중 구간으로 읽힌다.
- 되돌림 버튼을 두지 않고 전송 원의 순환으로 냈다. 원고가 버튼 이름을 주지 않으므로 글자 있는 버튼을 만들지 않는다. 세 요청을 다 보낸 뒤 한 번 더 누르면 정지 상태로 돌아간다.
- 입력 칸에 깜빡이는 커서를 두지 않았다. 무대에서 깜빡임은 시선을 뺏고 캡처가 회차마다 달라진다.
- 단계 점을 두지 않았다. 조작이 셋이고 이력에 쌓인 항목 수가 이미 진행 표시다.

### drag-threshold

- 장치를 전폭에서 넓은 짝의 주열로 줄였다. 곁 문장이 있으면 장치가 전폭을 쓸 수 없다는 `advance-machine` 의 조합 규칙이 이 판에도 그대로 걸린다.
- 결과 게이지의 높이를 56 에서 112 로 올렸다. 장치 안에 머리 행과 게이지와 조작부 셋뿐이라 56 으로 두면 빈 칸이 두 군데 110px 씩 남는다.
- 맺음 조건은 택소노미의 "양 끝을 다 지나 봤을 때" 대신 이 명세의 "적중률 60% 이상" 을 썼다. 값 자체가 메시지인 쪽에서는 값의 문턱이 조건이다. "넘으면" 을 60 이상으로 읽었다. Space 가 0, 60, 100 순서로 서므로 60 에서 켜져야 조작과 조건이 맞물린다.
- 게이지 호버의 계산 내역을 기준 표기와 같은 칸에 불투명도로 겹쳤다. 아래에 칸을 더하면 장치 높이가 조작에 따라 달라진다.
- 핸들과 트랙을 3쪽 겹침 비교의 경계 핸들과 같은 부품으로 만들었다. 한 발표에서 끌기가 두 쪽에 걸리므로 형태를 하나로 둔다.

### 세 판 밖에서 걸린 것

- 좌우 여백 검사가 kicker 와 쪽 번호만 재고 있었다. 검증 덱 1호의 관찰 창은 x 1360~1920 에 놓여 오른쪽 여백 80 을 침범하는데도 그 검사를 통과했다. 이 덱의 `qa/gates.mjs` 는 보이는 요소 전수로 좌우 여백을 다시 잰다.
- 레포 공용 `qa/fluid-gate.mjs` 의 호버 검사는 `filter` 를 읽지 않는다. 밝기만 바꾸는 호버 반응은 그 게이트에 안 잡힌다. 겨냥 대상의 반응은 링이나 면 색으로 낸다.
