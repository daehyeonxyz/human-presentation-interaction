- 항목 1 본문: 검색과 파일 읽기의 중간 결과는 서브에이전트 창에 남고

- 맺음: 없음

## 3쪽 (advance-machine, 등급 2)

- kicker: CONTEXT
- 제목: **컨텍스트** 보호
- 부제: Main window · Subagent window
- 장치 머리: 같은 조사 작업을 두 방식으로 진행한 컨텍스트 사용량 (예시)
- 게이지 이름 1: 직접 조사한 메인 창
- 게이지 이름 2: 위임한 메인 창
- 단계 라벨: 검색 / 파일 읽기 / 교차 확인 / 결론
- 버튼: 다음 단계
- 버튼 끝: 다시
- 게이지 1 캡션: 중간 결과가 전부 대화에 쌓인다
- 게이지 2 캡션: 마지막 보고 한 건만 받는다
- 곁 열 머리: 단계마다 서브에이전트 창에 남는 것
- 곁 열 항목 (단계 라벨 넷과 짝):
  - 검색: 검색 결과 목록과 훑어본 파일 경로
  - 파일 읽기: 파일 본문 전체와 인용 후보
  - 교차 확인: 서로 어긋난 대목의 대조 기록
  - 결론: 보고 한 건만 메인 창으로 돌아간다
- 맺음: 같은 결론을 받고 메인 창 사용량은 80% 와 10% 로 갈린다 (예시)

## 4쪽 (simulate-console, 등급 3)

- kicker: PARALLEL
- 제목: **병렬** 디스패치
- 부제: One dispatch · Three agents
- 에이전트 이름: 조사 A · 조사 B · 조사 C
- 트랙 부연 (이름 아래 한 줄씩):
  - 조사 A: 결제 모듈의 의존성 목록
  - 조사 B: 지난 릴리스의 회귀 이력
  - 조사 C: 테스트가 비어 있는 구역
- 트랙 단계 라벨: 대기 / 진행 / 보고
- 관찰 창 머리: 메인 창에 도착한 보고
- 관찰 창 상시 표시: 경과 (예시) 표기와 보고 수 "0 / 3"
- 보고 항목: 조사 A 결론 · 조사 B 결론 · 조사 C 결론
- 인스펙터 카드 (호버 미리보기와 클릭 고정): 작업 내용 한 줄과 토큰 사용량과 걸린 시간
  - 조사 A 작업 내용: 의존성을 훑어 충돌 후보 2건 정리
  - 조사 B 작업 내용: 릴리스 노트 9건에서 회귀 3건 정리
  - 조사 C 작업 내용: 커버리지 보고서에서 빈 구역 5곳 정리
  - 수치 (예시, 이 값이 정본): A 18k 토큰 · 2분 / B 26k 토큰 · 3분 / C 31k 토큰 · 4분
  - 상시 표시의 경과는 0분에서 4분까지 오른다 (예시)
- 맺음: 세 건을 순차로 돌리면 9분이고 병렬이면 가장 긴 한 건의 4분이다 (예시)

## 5쪽 (point-map, 등급 2)

- kicker: PROMPT
- 제목: 위임 프롬프트의 **구조**
- 부제: Anatomy of a dispatch prompt
- 왼쪽 예문 (구획별로 나눠 표시):
  - 구획 1: 레포는 ~/projects/demo 이고 git 저장소다
  - 구획 2: qa 폴더의 게이트 스크립트가 왜 실패하는지 원인을 찾아
  - 구획 3: 고치지는 말고 원인과 근거 파일 경로만 보고해
  - 구획 4: 끝나면 실패 원인 한 줄과 재현 명령을 남겨
- 오른쪽 규칙 목록 (이름과 부연 한 줄):
  - 규칙 1: 단독으로 성립하는 배경
    없으면 에이전트가 레포를 찾는 데 첫 시간을 쓴다
  - 규칙 2: 목표는 하나
    둘이면 둘 다 절반씩만 진행된 보고가 온다
  - 규칙 3: 범위의 경계
    없으면 원인 조사가 수정 커밋까지 번진다
  - 규칙 4: 보고 형식 지정
    없으면 보고를 받은 뒤 다시 되묻게 된다
- 맺음: 네 구획이 다 있으면 대화 맥락 없이 이 프롬프트만으로 실행된다

## 6쪽 정리 (accumulate-recap)

- kicker: RECAP
- 되짚기 항목 (이름과 부연 한 줄):
  - 컨텍스트 보호: 중간 결과는 서브에이전트 창에 남는다
  - 병렬 탐색: 독립인 조사만 나란히 보낸다
  - 관점 분리: 구현과 검증의 컨텍스트를 가른다
  - 80% 와 10%: 같은 결론을 받은 두 메인 창의 사용량 (예시)
  - 9분과 4분: 순차 합계와 병렬의 가장 긴 한 건 (예시)
  - 위임 프롬프트 네 구획: 배경과 목표와 경계와 보고 형식
- 선언: 위임은 메인 컨텍스트를 **아끼는** 방법이다
- 다음 물음: 어디까지 위임하고 무엇을 메인에 남길까
