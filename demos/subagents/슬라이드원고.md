# 서브에이전트와 병렬 작업 — 슬라이드 원고

인쇄 층의 단일 원본이다. 구현은 이 글자를 앉히기만 하고 새 문장을 만들지 않는다. 강조 낱말은 굵게 표시한다.

## 1쪽 표지 (cover-stage)

- 제목: 서브에이전트와
  병렬 작업 (두 줄. 줄 나눔은 이 표기가 정본이다)
- 태그라인: 메인 컨텍스트를 지키면서 여러 갈래를 동시에
- 오른쪽 위 영문: CLAUDE CODE SUBAGENTS
- 오른쪽 아래 영문: human-presentation-interaction demo deck 01

## 2쪽 (pick-list)

- kicker: WHY
- 제목: 서브에이전트를 쓰는 **세 가지** 이유
- 부제: Context isolation · Parallelism · Perspective
- 항목 1 이름: 컨텍스트 보호
- 항목 1 펼침: 검색과 파일 읽기가 만든 중간 결과는 서브에이전트 안에 남고
  메인 창에는 결론만 돌아온다
- 항목 2 이름: 병렬 탐색
- 항목 2 펼침: 서로 의존하지 않는 조사 여러 건을 동시에 보낸다
- 항목 3 이름: 관점 분리
- 항목 3 펼침: 구현한 눈과 검증하는 눈을 다른 컨텍스트로 가른다
- 맺음: 세 가지 전부 컨텍스트가 **자원**이라는 사실에서 나온 이유

## 3쪽 (advance-machine)

- kicker: CONTEXT
- 제목: 위임하면 메인 컨텍스트가 **지켜진다**
- 부제: Main window · Subagent window
- 장치 머리: 같은 조사 작업을 두 방식으로 진행한 컨텍스트 사용량 (예시)
- 게이지 이름 1: 직접 조사한 메인 창
- 게이지 이름 2: 위임한 메인 창
- 단계 라벨: 검색 / 파일 읽기 / 교차 확인 / 결론
- 버튼: 다음 단계
- 버튼 끝: 다시
- 곁 문장: 중간 결과는 서브에이전트 창에 쌓이고
  메인 창에는 마지막 보고 한 건만 돌아온다
- 맺음: 위임의 값어치는 답이 아니라 **남겨 둔 컨텍스트**

## 4쪽 (simulate-console)

- kicker: PARALLEL
- 제목: 병렬 디스패치는 **동시에** 진행된다
- 부제: One dispatch · Three agents
- 조작 안내는 없음. 재생 버튼과 단계 점이 형태로 알린다
- 에이전트 이름: 조사 A · 조사 B · 조사 C
- 트랙 단계 라벨: 대기 / 진행 / 보고
- 관찰 창 머리: 메인 창에 도착한 보고
- 보고 항목: 조사 A 결론 · 조사 B 결론 · 조사 C 결론
- 인스펙터 카드 (호버 미리보기와 클릭 고정): 각 에이전트의 작업 내용과 토큰 사용량 (예시)
- 맺음: 벽시계 시간은 **가장 느린 하나**가 정한다

## 5쪽 (pick-contrast)

- kicker: TIME
- 제목: 순차와 병렬은 **걸린 시간**이 다르다
- 부제: Sequential · Parallel
- 왼쪽 블록 이름: 순차 실행
- 왼쪽 본문: 세 건이 한 줄로 이어져
  전체 시간은 세 건의 합 (예시 9분)
- 오른쪽 블록 이름: 병렬 실행
- 오른쪽 본문: 세 건이 나란히 진행되어
  전체 시간은 가장 긴 한 건 (예시 4분)
- 맺음: 독립인 작업만 나란히 보낼 수 있고 **의존 관계**가 순서를 정한다

## 6쪽 (point-map)

- kicker: PROMPT
- 제목: 위임 프롬프트에는 **구조**가 있다
- 부제: Anatomy of a dispatch prompt
- 왼쪽 예문 (구획별로 나눠 표시):
  - 구획 1: 레포는 ~/projects/demo 이고 git 저장소다
  - 구획 2: qa 폴더의 게이트 스크립트가 왜 실패하는지 원인을 찾아
  - 구획 3: 고치지는 말고 원인과 근거 파일 경로만 보고해
  - 구획 4: 끝나면 실패 원인 한 줄과 재현 명령을 남겨
- 오른쪽 규칙 목록:
  - 규칙 1: 단독으로 성립하는 배경
  - 규칙 2: 목표는 하나
  - 규칙 3: 범위의 경계
  - 규칙 4: 보고 형식 지정
- 맺음: 좋은 위임 프롬프트는 **처음 보는 사람**도 그대로 실행할 수 있는 글

## 7쪽 정리 (accumulate-recap)

- kicker: RECAP
- 되짚기 항목: 컨텍스트 보호 / 병렬 탐색 / 관점 분리 / 남겨 둔 컨텍스트 / 가장 느린 하나 / 위임 프롬프트의 구조
- 선언: 서브에이전트는 컨텍스트를 지키는 **분업**이다
- 다음 물음: 어디까지 위임하고 무엇을 메인에 남길까
