# daehyeonxyz 발표 철학 — 실측 증류본

이 문서는 인터랙티브 프레젠테이션 스킬의 기획·구성·서술·디자인 기준의 뿌리다. 근거는 전부 사용자의 실물 기록이며, 각 절에 출처 경로를 붙인다. 추정은 표시한다.

주요 출처:

- 발표 원고 초안 관찰 — 세미나 7종과 과제 발표와 강연 대본 2종의 정성 관찰 (9항목)
- 확정된 문체 팩 — 발표 9편 1,246문장의 실측 지문. 현재는 `outputs` 스킬이 이 기준을 갖는다
- 디자인 검토 기억 — 발표는 논리의 시각화라는 관점과 AI 티 신호 목록
- 작업 방식 기록 — 본인 글 306편 실측
- 실전 기획 사례 — 기획서와 팀 노트
- 실물 HTML 세미나 덱 — 디자인 시스템 노트와 QA 캡처 수백 장

## 1. 발표관 — 왜 발표하는가

- **발표는 꾸밈이 아니라 논리를 보여주는 장치다.** "속 빈 강정이 아니라 꽉 참"이 품질 기준이다. (design/memory.md, working-style.md)
- 자기서사 3단(정보를 수집하고 → 구조화·논리화해 처리하고 → 공동체에 공유한다)의 세 번째 항이 발표다. 그래서 발표를 항상 본인이 맡는다. (working-style.md 신념 절)
- 페이지 수를 늘리는 것보다 논리가 이어지는 것이 우선이다. 슬라이드는 문서가 아니라 말의 시각 보조이고, 완결 서술은 대본 레이어가 맡는다.

## 2. 덱의 논리 구조

- **슬라이드당 주장 하나.** 데이터·표·다이어그램 우선, 문장 나열 최소화. (design/memory.md)
- 큰 골격은 **문제 → 접근 → 방법 → 결과 → 논의 → 소회**. 학술 IMRaD를 따르되 끝에 개인 성찰을 단다. (ppt-narration-draft §4)
- **RQ·가설·스터디를 번호로 센다** (RQ1~3, H1~H3, STUDY 1~5). 논증 단위를 명시 번호로 끊어 따라가기 쉽게 한다.
- **한계를 결론 직전에 배치한다.** 남의 논문을 리뷰할 때도 약점을 먼저 인정하고 결론으로 간다.
- **닫는 슬라이드는 성찰·전환이다.** "느낀점" 또는 "토론주제"로 끝내고, 다룬 내용을 자기 문제의식으로 되당긴다 ("우리 연구도 결국 DSCT의 연장선이다"). Q&A 단독 슬라이드로 끝내지 않는다.
- **정의 → 대비 → 사례의 3연.** 개념을 한 줄로 정의하고, 대립쌍으로 가르고 (가언 vs 정언), 실제 사례를 붙인다.

## 3. 페이지 내부 구성

- **3겹 위계**: 상단 러닝 헤더(영문 섹션명: Introduction / Key Idea / Results ...) + 한국어 제목 + 개조식 본문. 슬라이드 하단에는 그날의 단계 카테고리 라벨을 반복 배치해 지금 어느 국면인지 고정 표시한다.
- **번호 매긴 챕터 디바이더**로 장을 끊는다 ("선한 의지와 좋은 것들 / 1", "Section 1 What to Know").
- **근거·출처를 감추지 않는다.** 인용 번호 [nn]을 본문 옆에 그대로 노출한다.
- 정보 밀도의 실측 기본값 (DCA 브리프보드): 배경 2~3문단, 아이디어 1~2문단, 실행 3단계, 기대효과 3개. 장르에 따라 밀도 기준이 달라진다 (기획서 덱 = "깔끔하고 흐름 매끄럽게", 브리프보드 = "통통 튀게". team-notes.md).

## 4. 서술 (슬라이드 텍스트)

- **제목은 명사·명사구로 종결하고 마침표를 붙이지 않는다.** ("기존 DSCT의 한계", "논문 목표")
- **"영문 핵심어 : 한국어 풀이" 콜론 패턴.** 영어 용어를 던지고 콜론 뒤에 그날 쓸 한국어 프레이밍을 붙인다. ("AI-assisted decision-making : 의사결정 지원 도구로서의 AI")
- 제목 자리에 **수사적 질문**도 쓴다. ("긴 스마트폰 사용은 항상 더 나쁘게 느껴지는가?")
- 본문은 **개조식(명사 종결) + 한 줄 한 개념.** 완결 서술 문단을 슬라이드에 얹지 않는다.
- 지문 수치: 명사형 종결 38% 최다, 반말 평서 37% 비등. 문장 길이 중앙값 64.5자, **쉼표 중앙값 0개** (슬라이드에서 쉼표를 쓰지 않는다).
- 열거 표지("먼저, 둘째, 셋째, 마지막으로")는 발표 장르에서 실사용하는 순서 안내 장치라 지우지 않는다.
- 금지 목록 26개의 SSOT 는 `outputs` 스킬의 `standards/banned-words.json` 이다.

## 5. 대본 (구어 레이어) — 슬라이드와 다른 결

- 대본은 **합쇼체 완결 구어체**다. "안녕하세요, 팀3 발표 시작하겠습니다", "~하겠습니다 / ~죠". 청중을 직접 부른다 ("여러분들도 ... 경험이 있으실 것 같은데").
- **질문으로 끌고 예시로 받친다.** ("두바이 초콜릿, 어디에서 시작된 건지 아시나요?" → 틱톡 사례)
- 개념어를 던지기 전에 정의를 먼저 풀어 준다.
- 슬라이드=개조식, 대본=완결 구어의 **이중 트랙**이 확립된 습관이다. 스킬도 두 레이어를 분리 생성해야 한다.

## 6. 수사 장치

- **일관된 구체 메타포를 한 덱 끝까지 민다.** Prompt/Context/Harness Engineering을 말(馬) 비유 3단으로 꿴 사례, 스마트폰 시각화 = "디지털 인바디", 코칭 LLM = "헬스 트레이너". 유추가 사고의 뼈대다 (working-style.md P14).
- **일상 예시로 진입한다.** 유튜브 "아직도 시청 중이신가요?", 두바이 초콜릿 유행처럼 익숙한 것에서 개념으로 올라간다.
- **인용부호로 원문·발화를 살린다.** 칸트 정식을 따옴표 안에 그대로 인용.

## 7. 강조와 디자인

- **볼드 = 핵심 명사구·대비의 축. 색 = 구조 신호만** (섹션 바·카테고리 라벨). 무지개색 강조 금지. 역할이 갈린다.
- 실물 덱의 디자인 시스템 (design-system-reference-notes.md): 1920x1080, 배경 `#f8f8f8`, 단일 액센트 (`#28d4c8` 계열), Pretendard/Noto Sans KR, 카드 radius 12-20px에 그림자 없음, 위계는 크기·굵기로.
- **사용자 고유 slop 신호** (design/memory.md): em-dash, 기계적 대구, 빈 요약문장, 성의 없는 회색 작은 폰트, **어색한 줄바꿈**, 위계 없는 카드/원 장식, radius 불일치. 비강조를 옅은 회색·낮은 투명도로 대신하지 않는다.
- anti-AI 규칙 실사용 목록: 보라/파랑 그라데이션 금지, generic hero metric 금지, nested cards 금지, 장식 그림자 금지, 근거 없는 3카드 그리드 금지.
- 이모지 미사용. 제목·개조식에 마침표 없음.

## 8. 기획 방법 (덱 이전 단계)

DCA 기획서가 실전 표본이다. 구조: **한 줄 정의 → Background (시장 / 브랜드 자산 / 소비자 인사이트 / 문제 정의) → 목표 (KPI 표) → 타깃 (이중 타깃을 하나의 언어로 관통) → 빅 아이디어 → 구조 (참여 루프 4단계) → 상세 → 기대효과 → 심사위원 60초 체험 시나리오**.

- 결론(한 줄 정의)을 맨 앞에 둔다. 문제 정의는 재정의를 거친다 ("소주의 위기는 알코올의 위기가 아니라 역할의 위기다").
- **청중 분석이 선행한다.** DCA에서는 수상작 리서치로 심사 기준("참신함 비중이 큼")을 먼저 확인했고, "심사위원 60초 체험 시나리오"까지 설계했다. 청중이 산출물을 체험하는 동선 자체를 기획한다.
- 각 단계가 다음 단계의 동기를 만드는 **루프 구조**로 짠다.

## 9. 제작·검증 방식

- **SSOT 원칙**: 편집 가능한 구조화 원본에서 시각물을 파생시킨다. 비트맵으로 굳는 자동생성은 거부한다. (design/memory.md, rules/behavior)
- **완료 판정은 실제 렌더 관찰이다.** file://로 실제 구동해 보고 끝낸다. http 서버 검증만으로 끝내지 않는다 (선행 발표 스킬의 실증). 정적 검증은 레이아웃 충돌(패널 겹침)을 못 잡는다는 것이 실증됐다.
- **반복 QA가 제작 과정이다.** 실물 덱 폴더에 qa-layout-v2~v3, qa-final-tone, qa-title-structure 등 수백 장의 렌더 캡처가 남아 있다. 레이아웃·톤·제목구조를 렌더 보며 반복 개선한다.
- 소스에 없는 주장은 슬라이드에 넣지 않는다. 숫자·인용은 출처를 스피커노트에 병기한다 (선행 발표 스킬의 규율).
- 대량 제작 전 표현 목표 목업을 선승인받고, 상용 레퍼런스와 나란히 놓아 판정한다 (rules/behavior).

## 10. 스킬 설계에 직결되는 함의

1. 스킬의 첫 단계는 디자인이 아니라 **발표의 목적·청중·핵심 메시지 인터뷰**여야 한다 (기획 → 구성 → 서술 → 디자인 → 검증의 풀 파이프라인).
2. 페이지마다 핵심 메시지 하나를 먼저 확정하고, 레이아웃은 그 메시지의 논리 구조를 시각화하는 수단으로 고른다.
3. 슬라이드 텍스트와 대본을 **다른 문체로 이중 생성**한다 (ppt-narration 팩 / voice-speech 참조).
4. 줄바꿈·여백·위계는 slop 신호 목록으로 검증한다. 어색한 줄바꿈은 사용자가 명시한 감식 항목이다.
5. 무엇을 말로, 무엇을 인터랙션으로, 무엇을 텍스트로 배분할지가 설계 단계의 1급 결정이다.
6. 완료는 렌더 관찰 + 목업 선승인 + 나란히 비교로만 선언한다.
