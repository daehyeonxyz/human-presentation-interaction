# content.json 작성 기준

글자 수는 한글 1자를 1, 영문·숫자·공백을 0.5로 센다. `scripts/build.py` 가 같은 방식으로 검사한다.

## 칸 목록

| 칸 | 화면 위치 | 개수 | 항목당 상한 | 쓰는 법 |
|---|---|---|---|---|
| `name` | 제목 아래 호출어, 파일 카드 제목 | 1 | - | 스킬 폴더 이름 그대로 (`svic-formal-format`) |
| `title` | 왼쪽 위 큰 제목 | 1 | 12 | 사람들이 부를 스킬의 한국어 이름. 설명을 붙이지 않는다 (`삼성 양식 보고서 작성`) |
| `when` | 상자 1 "이럴 때 씁니다" | 3 | 26 | 스킬 description 의 트리거 표현과 사용 상황 |
| `does_lead` | 상자 2 첫 줄 | 1 | 34 | 선택. 산출물이 여럿이거나 상황에 따라 경로가 갈리는 스킬에서 전체를 한 문장으로 말한다. 그 아래 `does` 는 산출물이나 경로별 항목이 된다 |
| `does[].t` | 상자 2 항목 제목 | 4 | 14 | 사용자가 받는 것의 이름. 산출물이면 산출물 이름과 형식(`기술 실사 브리프 · HTML`) |
| `does[].d` | 상자 2 항목 설명 | 4 | 32 | 그것이 누구에게 어디에 쓰이는지 한 줄. 항목 수는 1~4개로 내용에 맞춘다 |
| `files[].path` | 파일 카드 | 4 | 22 | 스킬 폴더 기준 상대 경로. 파일이 네 개보다 많으면 주요 파일만 넣거나 폴더 단위로 묶는다. 폴더는 `references/` 처럼 `/` 로 끝내면 폴더 아이콘이 붙는다 |
| `files[].role` | 파일 카드 오른쪽 | 4 | 10 | 그 파일의 역할 (지침, 줄 길이 검사, 양식, 예시) |
| `model` | 입력창 모델 이름 | 1 | - | 생략하면 `Sonnet 5` |
| `chat` | 오른쪽 채팅창 | 4~6 | - | 아래 채팅 규칙 |

왼쪽 열 높이가 고정이라 `does_lead`(있으면 1) + `does` 개수 + `files` 개수가 8을 넘으면 안 된다. 넘으면 사람용 안내 파일(README 등)을 한 줄로 묶는다.

## 채팅 규칙

메시지 하나는 아래 키를 가진다. 필요한 키만 쓴다.

| 키 | 대상 | 내용 |
|---|---|---|
| `role` | 모두 | `user` 또는 `assistant`. 첫 메시지는 `user` |
| `text` | 모두 | 본문 한 줄, 상한 70. `/스킬이름` 은 파란 글자로 표시된다 |
| `attach` | user | 첨부 파일 이름 목록 |
| `skill` | assistant | 넣으면 "스킬이름 스킬 사용" 표시가 붙는다. 스킬이 처음 호출되는 답에 한 번만 넣는다 |
| `list` | assistant | 점 목록, 항목당 상한 34 |
| `md` | assistant | 채팅 답 본문을 마크다운으로(10줄, 줄당 34). `###` 소제목, `- ` 목록, `**굵게**` 를 Claude 앱 답변처럼 그린다. 파일 없이 채팅으로 답하는 스킬의 결과를 보여 줄 때 쓴다 |
| `preview` | assistant | 결과물 미리보기. 글 결과물은 `title` 과 `lines`(9줄까지, 줄당 48)로 종이를 그린다. 보고서처럼 서식 있는 문서는 바탕체 종이로 그리고, md 파일 결과는 `style: "md"` 를 넣고 `lines` 에 마크다운 원문을 그대로 넣는다. 노션·옵시디언처럼 frontmatter 는 속성 표로, `#`·`##`·`###` 은 제목으로, `- ` 는 목록으로, `` `코드` `` 와 `**굵게**` 는 서식으로 그린다(13줄까지). 페이지 제목은 `title` 에 확장자 없이 넣는다. json·검색 결과처럼 그 밖의 서식 없는 결과는 `style: "plain"` 으로 본문 서체로 그린다. 화면·이미지 결과물은 `image`(예시 폴더 기준 파일 경로)로 그림을 넣는다. 한 장에 하나. 파일을 만드는 스킬에만 넣는다 |
| `file` | assistant | 결과 파일 카드에 표시할 파일 이름 |

채팅창 높이는 고정이라 담을 수 있는 양이 정해져 있다.

- 결과물 미리보기(`preview`)는 스킬이 파일을 만들 때만 넣는다. 읽는 사람이 "무엇을 받는지"를 눈으로 확인하는 곳이다.
- 찾기·요약·답변처럼 결과가 채팅으로 나오는 스킬은 미리보기 종이를 만들지 않는다. 답 본문을 `md` 로 채팅 안에 그대로 보여 준다.
- 미리보기가 든 답은 대화를 배치하고 남은 채팅창 높이를 모두 받는다. 종이는 아래로 길어지고, 그림은 그 높이 안에서 최대 크기로 들어간다. 그래서 대화가 짧을수록 미리보기가 커진다.
- 미리보기를 넣으면 메시지는 5개까지, 목록은 3줄까지다.
- 흐름은 "요청 → 스킬이 하는 일이 드러나는 답 → (확인) → 결과"로 짠다. 확인 단계가 있는 스킬은 그 단계를 반드시 보여 준다.
- 첫 요청은 실제 사용 장면에서 고른다. 그 일을 할 때 손에 있는 자료(피치덱 PDF, 명단 엑셀, 회의록)를 `attach` 로 붙이고 업무 맥락을 말하게 한다. "○○ 추가해 줘"처럼 기능 이름을 부르는 데모 문장은 쓰지 않는다. 기준과 예시는 `SKILL.md` 2단계에 있다.
- 장면이 여럿이면 한 채팅에 몰지 않는다. 채팅 하나에는 장면 하나를 넣는다.
- 미리보기의 `lines` 는 공백을 그대로 살려 고정폭처럼 보여 준다. 들여쓰기가 의미 있는 양식이면 공백 수를 원문과 맞춘다.

## 예시

`examples/svic-formal-format.json` 을 본다. 그 예시에서 칸마다 근거를 가져온 곳은 다음과 같다.

| 칸 | 근거 |
|---|---|
| `title` | 사용자가 정한 스킬 이름 "삼성 양식 보고서 작성" |
| `when` | description 의 트리거 표현('보고서', '결재용', '품의용', '기안')과 대상 주제 |
| `does` | 1장 작성 전 컨펌, 2장 표준 목차, 3장 개조식 문체, 5장 검토작업 |
| `chat[1].list` | 1장 컨펌 항목(제목, 섹션 구성, 표) |
| `preview.lines` | 3.3장 예시 문장 |
| `files` | 패키지에 실제로 든 파일 두 개 |
