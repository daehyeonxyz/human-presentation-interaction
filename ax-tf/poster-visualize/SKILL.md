# 공지 포스터 시각화

전사 메일에 붙이는 세로 포스터를 만든다. 받는 사람은 대표이사를 포함한 임직원 전체라서, 글로 깊게 설명하지 않고 한눈에 보이는 그림과 짧은 문장으로 전한다. 화면 구성은 블록을 골라 쌓는 방식이고 `content.json` 만 채운다. 색, 글꼴, 간격은 고정이다.

## 파일

```text
assets/poster.css          디자인 체계(색, 글꼴, 간격, 블록 모양). 고치지 않는다
assets/podium.png          1·2·3위 시상대 그림. 상금이나 수상자 이름을 얹는다
scripts/build.py           content.json 을 HTML 한 장으로 조립하고 규칙을 검사
scripts/capture.py         HTML 을 PNG 로 캡처하고 넘친 칸을 찾는다
references/content-guide.md  블록 종류와 칸별 작성 기준
examples/                  공모전 안내, 서비스 소개 공지, 수상자 발표 예시 (json, html, png)
```

## 절차

1. **목적과 재료 확인**
   - 무엇을 알리는지, 누가 받는지, 받는 사람이 읽고 무엇을 하면 되는지 정한다.
   - 공지에 들어갈 사실을 모은다. 누가, 언제부터, 어떤 주기로, 무엇을, 어떻게, 어디로 문의하는지다.
   - 사용자가 준 자료에 없는 날짜, 수치, 이름은 지어내지 않는다. 비어 있는 값은 `[[○월 ○일]]` 처럼 표시해 두고 사용자에게 묻는다.
   - 맨 위에 둘 그림을 정한다. 순위가 있으면 시상대, 화면이나 문서를 보여 줄 거면 그 캡처, 둘 다 없으면 그림 없이 제목만 쓴다.
   - 캡처 그림은 사용자에게 받는다. 받은 그림에 개인정보나 투자 정보처럼 전사에 돌리면 안 되는 내용이 있으면 가릴지 먼저 묻는다.

2. **구성 확인**
   - 제목, 맨 위 그림, 장 제목 목록, 장마다 쓸 블록을 표로 정리해 사용자에게 먼저 보여 주고 확인받는다.
   - 장은 세 개 안팎으로 둔다. 장마다 메시지는 하나다.
   - 수정 요청이 있으면 반영해서 다시 확인받는다.

3. **조립**
   - `references/content-guide.md` 를 읽고 `content.json` 을 쓴다. 비슷한 예시의 json 을 복사해 고치는 것이 가장 빠르다.
   - `python scripts/build.py content.json <이름>.html` 을 실행한다. Windows 는 `python`, macOS·Linux 는 `python3` 이다.
   - 고칠 곳이 출력되면 문장을 줄이거나 블록을 바꿔 다시 실행한다. 글꼴 크기나 CSS 를 바꿔서 맞추지 않는다.

4. **확인**
   - `python scripts/capture.py <이름>.html <이름>.png` 로 캡처한다. 넘친 칸이 출력되면 그 문장을 줄인다.
   - 캡처를 직접 보고 아래를 확인한다.
     - 나란한 카드와 패널의 아래 끝이 맞는가
     - 한 줄에 한 덩어리 뜻이 오도록 줄이 바뀌었는가
     - 강조색과 띠가 꼭 필요한 곳에만 있는가
   - 캡처할 수 없는 환경이면 HTML 을 브라우저로 열어 확인하고, 그 사실을 사용자에게 알린다.

5. **전달**
   - HTML 과 PNG 를 함께 전달한다. 메일 본문에는 PNG 를 붙인다.
   - HTML 은 그림을 파일 안에 넣었으므로 그 파일 하나만 있으면 열린다. 서체는 웹 서체라 인터넷이 되는 곳에서 연다.
   - 아직 채우지 않은 `[[...]]` 값과 확인이 필요한 사실을 목록으로 함께 알린다.

## 문장 기준

- 제목은 소식지나 사내 보도 제목처럼 쓴다. 예: "삼성벤처투자 데일리 뉴스레터", "제1회 AX 공모전 수상자 발표".
  - "~를 보냅니다", "~를 소개합니다" 같은 홍보 문장으로 쓰지 않는다. 모집 공지처럼 행동을 부르는 글만 문장 제목을 쓴다(예: "출장 보고서를 만들어 주는 SKILL을 찾습니다").
  - "투자팀별" 처럼 서류 말투는 피한다.
- 장 제목은 꾸밈 없는 명사로 쓴다. "두 가지 뉴스레터"처럼 개수를 넣지 않는다.
- 설명 문장은 전 직원이 읽으므로 "~습니다"로 쓴다. 한 블록 안에서 말투를 섞지 않는다.
- 비유, 의인화, 뭉뚱그린 말("닿습니다", "세 갈래", "움직임", "자리")을 쓰지 않는다. 정확한 명사와 서술어로 쓴다.
- 예시 문장은 실제로 쓰는 장면에서 고른다. 누구나 보낼 수 있는 크기의 요청으로 쓴다. 모두가 받는 공용물의 형식을 바꿔 달라는 요청은 개인이 하기 어렵다.
- 문의처는 맨 아래 한 줄로 낮춰 둔다.

## 화면 기준

- 맨 위 그림은 포스터의 얼굴이다. 화면 캡처를 쓰면 실제 화면이 충분히 보이게 높이를 넉넉히 준다.
- 띠(`band`)는 한 장에 한 번, 가장 전하고 싶은 문장 하나에만 쓴다. 부수적인 기능을 띠나 짙은 상자로 강조하지 않는다.
- 숫자는 옆 글자와 크기 균형을 맞춘다. 수치 카드의 숫자를 제목보다 크게 키우지 않는다.
- 내용을 구체적으로 늘어놓기보다 그림으로 보여 준다. 받는 사람이 대표이사까지라면 더욱 그렇다.
- 빈 곳을 채우려고 내용을 지어 넣지 않는다. 칸의 크기와 정렬로 맞춘다.

## 체크리스트

- [ ] 구성(제목, 맨 위 그림, 장 목록)을 사용자에게 확인받았는가
- [ ] 모든 사실이 사용자 자료에 근거하는가. 비어 있는 값은 `[[...]]` 로 표시했는가
- [ ] 전사에 돌리면 안 되는 이름, 금액, 내부 자료를 가렸는가
- [ ] `build.py` 와 `capture.py` 가 고칠 곳 없이 통과했는가
- [ ] HTML 과 PNG 를 함께 전달하고 남은 확인 사항을 알렸는가
