# layout-taxonomy — 레이아웃은 택소노미에서 고른다

화면 레이아웃을 설계·재구성할 때 쓰는 핵심 스킬이다. 사용자가 제공한 분류 체계(2026-07-31)를 그대로 바인딩한다. 원본은 같은 폴더의 [taxonomy.md](taxonomy.md) 다. 6부 23분류 139개 키워드이고, 에디토리얼 기본 원리부터 웹 UX·UI 아키타입과 실험 레이아웃까지 담는다.

## 언제 쓰나

화면 하나의 구조를 새로 잡거나 다시 잡을 때 반드시 쓴다. UI 와 디자인 시스템(색·부품·질감)은 그다음이다. 순서가 뒤집히면 반려된다.

## 어떻게 쓰나

1. **화면의 목적과 태스크 플로우를 먼저 적는다.** 이 화면에서 사용자가 무엇을 하러 오고 어떤 순서로 움직이는가. 인터랙션 하나하나의 의미가 이 플로우에서 나와야 한다.
2. **taxonomy.md 에서 패턴을 지목한다.** 공간 모델(fluid/fixed/hybrid)과 영역 정책을 최상위에서 먼저 정하고, 페이지 아키타입 하나, 그 아래 그리드·위계·여백·읽기 경로 패턴을 고른다. 결정마다 패턴 ID 를 근거로 적는다(예: `sidebar-nav-shell` + `split-view-master-detail` + `manuscript-grid`).
3. **조합 규칙을 지킨다.** 각 패턴의 Good With 는 함께 쓰고 Avoid With 는 같은 화면에 두지 않는다. Best For 와 Avoid For 로 그 화면에 맞는지 검증한다.
4. **안정성 가드레일은 항상 적용한다.** overflow-containment, intrinsic-sizing, cls-prevention, stacking-discipline 은 선택이 아니라 기본이다.
5. **산출물에 패턴 지도를 남긴다.** 화면마다 어떤 패턴을 왜 골랐는지 한 줄씩. 이것이 있어야 다음 사람이 레이아웃을 임의로 못 흔든다.

## 금지

- 택소노미에 없는 임의 구조를 이름 없이 만드는 것. 새 패턴이 정말 필요하면 어느 패턴의 변형인지 명시한다.
- 패턴 이름만 빌리고 Structure·Build 명세를 안 따르는 것.
- 레이아웃 결정 없이 부품 배치부터 시작하는 것.
