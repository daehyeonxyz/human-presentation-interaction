# AX 101 현실 대조표

2026-09-04에 Anthropic 공식 문서(platform.claude.com/docs, claude.com/docs, code.claude.com/docs, support.claude.com)와 대조했다. platform.claude.com, claude.com/docs, code.claude.com은 원문을 직접 읽었다. support.claude.com과 anthropic.com은 이 환경의 프록시가 막아 검색 색인의 원문 발췌로 확인했고, 그 항목은 (발췌)로 표시했다. 발표 전에 그 페이지는 브라우저로 한 번 열어 보길 권한다.

판정: 맞음 / 부분 / 틀림 / 확인불가. "덱"은 15차 장표와 첫 대본이 했던 주장이다.

## 모델

| # | 덱의 주장 | 판정 | 현실과 근거 |
|---|---|---|---|
| M1 | 라인업은 Haiku 4.5, Sonnet 5, Opus 5, Fable 5 | 부분 | 현행은 Haiku 4.5, Sonnet 5, Opus 5, **Fable 5.1**(2026-09-01 출시). Fable 5는 Legacy. Sonnet 5.1, Opus 5.1은 없다. https://platform.claude.com/docs/en/models/overview |
| M2 | 출시와 컷오프 | 부분 | Haiku 4.5: 출시 2025-10-15, 신뢰 컷오프 2025-02(학습 데이터 컷오프 2025-07). Sonnet 5: 2026-06-30, 2026-01. Opus 5: 2026-07-24, 2026-05. Fable 5: 2026-06-09, 2026-01. Fable 5.1: 2026-09-01, 2026-06. 각 모델 overview 페이지 |
| M3 | 큰 모델일수록 파라미터가 많다 | 확인불가 | Anthropic은 파라미터 수를 공개하지 않는다. 공식 구분 축은 지능(capabilities), 속도(latency), 비용, effort 넷. https://platform.claude.com/docs/en/about-claude/models/choosing-a-model |

| M5 | Fable은 Mythos에 안전장치를 씌운 것 | 맞음 | "same model, different levels of safeguards". Mythos는 Project Glasswing 초대 전용. https://platform.claude.com/docs/en/models/mythos-5-1/overview |
| M6 | 컨텍스트 윈도우 20만 / 100만 | 부분 | Sonnet 5, Opus 5, Fable 5.1은 100만이 기본이고 추가 요금 없음. Haiku 4.5만 20만. claude.ai에서는 플랜과 모델에 따라 1M, 500K, 200K가 섞여 있고 Sonnet 5는 500K에서 자동 압축(발췌). https://platform.claude.com/docs/en/build-with-claude/context-windows |

## Effort와 사고

| # | 덱의 주장 | 판정 | 현실과 근거 |
|---|---|---|---|
| E1 | 단계는 Low, Medium, High, xhigh, Max. 기본값 High | 맞음 | API `output_config.effort`, 기본 high. 앱에도 다섯 단계이며 모델마다 "Default" 표시(발췌). https://platform.claude.com/docs/en/build-with-claude/effort |
| E2 | 토큰 예산이 아니라 신호 | 맞음 | "Effort is a behavioral signal, not a strict token budget." 같은 페이지 |
| E3 | 모델에 대해 정할 수 있는 건 두 가지 | 맞음 | 전송 버튼 옆 모델 메뉴에서 모델과 Effort를 고른다(발췌). 도움말에 남아 있는 사고(thinking) 토글은 레거시라 다루지 않는다(발표자 결정). https://support.claude.com/en/articles/8664678 |
| E4 | Opus 5는 사고를 끌 수 없다 | 삭제 | 사고 토글 자체를 다루지 않으므로 대본에서 뺐다 |
| E5 | 모든 모델에 Effort가 있다 | 틀림 | Haiku 4.5는 Effort 미지원. xhigh는 일부 모델만. effort 페이지 |

## 토큰과 비용

| # | 덱의 주장 | 판정 | 현실과 근거 |
|---|---|---|---|
| T1 | 토큰은 형태소, 단어, 구절 하나일 수 있다 | 부분 | "words, subwords, characters, or even bytes". 영어 약 3.5자에 한 토큰. 한국어 비율은 공식 수치 없음. https://platform.claude.com/docs/en/about-claude/glossary |
| T2 | 출력 토큰이 입력의 5배 | 맞음 | Haiku 1/5, Sonnet 2/10, Opus 5/25, Fable 10/50 달러. 전 모델 정확히 5배. https://platform.claude.com/docs/en/about-claude/pricing |
| T3 | 이전 입력은 저장해 두어 10%만 청구 | 맞음 | 캐시 읽기 0.1배. Fable 5.1만 0.025배. 캐시 쓰기는 1.25배(5분) 또는 2배(1시간). 같은 페이지 |
| T4 | 이전 입출력이 매번 다시 들어간다 | 맞음 | "each user message and assistant response accumulates within the context window, and previous turns are preserved completely". https://platform.claude.com/docs/en/build-with-claude/context-windows |
| T5 | 추론 과정도 출력 토큰 | 맞음 | 사고 토큰은 출력으로 과금. 현행 모델은 이전 턴의 사고 블록도 컨텍스트에 남아 다음 턴 입력으로 과금. 같은 페이지 |

## 컨텍스트 윈도우와 입력 레이어

| # | 덱의 주장 | 판정 | 현실과 근거 |
|---|---|---|---|
| C1 | 컨텍스트 윈도우는 모델의 작업 기억 공간 | 맞음 | "represents a 'working memory' for the model". context-windows 페이지 |
| C2 | 컨텍스트 엔지니어링 정의 | 맞음 | "the set of strategies for curating and maintaining the optimal set of tokens (information) during LLM inference"(발췌). https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents |
| C3 | 대화 시작 전에 설정 파일, 지침, 메모리, 도구, 스킬 설명, 프로젝트 지침이 들어간다 | 부분 | 항목은 맞다. 시스템 프롬프트에 날짜 등이 들어가고(공개 문서 있음), 스킬은 이름과 설명만 시작 시 로드, 도구 정의도 포함. **순서는 공식 근거 없음**. 도식은 구성도이지 순서도가 아니다. https://platform.claude.com/docs/en/release-notes/system-prompts/overview |
| C4 | 지침은 대화 시작에 자동으로 들어간다 | 부분 | 개인 Instructions는 모든 대화에 적용, 조직 지침은 "included in every message". 시점은 "매 메시지"가 정확. https://support.claude.com/en/articles/10185728 (발췌) |
| C5 | "Claude 지침"이라는 이름, 설정 > 일반 | 부분 | 공식 영문 명칭은 Instructions(profile instructions). 경로는 "좌하단 이니셜 클릭"으로만 기술. 한국어 UI 라벨은 캡처대로 쓰되 영문 명칭을 병기. 조직 지침(3,000자, 개인 지침보다 우선)이 따로 있다. https://support.claude.com/en/articles/14546867 (발췌) |
| C6 | 메모리는 대화에서 뽑아 쌓아 두고 다음 대화에서 참조 | 부분 | 현행은 Topics 단위 항목을 **대화 중에 읽고 갱신**한다. 설정 > 메모리 > Topics에서 편집, 삭제. "기억해 줘"로 즉시 추가 가능. https://support.claude.com/en/articles/11817273 (발췌) |
| C7 | 메모리 켜고 끌 수 있음 | 부분 | Team, Enterprise는 **기본 꺼짐**. Owner가 Organization settings > Capabilities에서 켜야 개인이 켤 수 있다. 프로젝트마다 메모리 공간이 따로 있다. 같은 페이지 (발췌) |
| C8 | 다른 AI에서 메모리 가져오기 | 부분 | Free, Pro, Max, Team만 명시. Enterprise 미기재. 실험 기능. https://support.claude.com/en/articles/12123587 (발췌) |
| C9 | 프로젝트 지식은 필요할 때 검색되어 들어간다 | 틀림 | 컨텍스트에 들어갈 만큼 작으면 **전체가 항상 들어간다**. 한도에 가까워지면 RAG 모드로 자동 전환해 검색(최대 10배 확장, 유료 플랜). 다시 작아지면 전체 포함으로 복귀. 프로젝트 내용은 캐시되어 한도에 재계산되지 않음. https://support.claude.com/en/articles/11473015 (발췌) |
| C10 | 첨부, 웹 검색, 프로젝트 지식은 넓은 의미로 다 RAG | 맞음 | 답변 전에 외부 자료를 찾아 그걸 근거로 생성한다는 뜻에서 셋 다 해당한다. Anthropic이 "RAG"라는 낱말을 쓰는 곳은 프로젝트 지식 문서뿐이지만 그건 명칭이지 작동 방식의 구분이 아니다. 웹 검색 결과와 첨부 내용은 입력 토큰으로 컨텍스트에 들어간다. https://platform.claude.com/docs/en/about-claude/pricing |
| C11 | 마크다운, CSV 권장 | 확인불가 | 공식 권장 없음. 비PDF 문서는 텍스트만 추출한다는 사실만 있다. https://support.claude.com/en/articles/8241126 (발췌) |
| C12 | 프로젝트는 입력 기준으로 나눈다 | 확인불가 | Anthropic의 분할 기준은 없다. 강사 권고로 표기. "Context is not shared across chats within a project unless the information is added into the project knowledge base." https://support.claude.com/en/articles/9519177 (발췌) |
| C13 | 팀 자료는 프로젝트 지식 또는 File System 커넥터 공유 폴더 | 틀림 | "File System"이라는 커넥터는 없다. 데스크톱 확장(Settings > Extensions)의 filesystem이거나 Cowork의 연결된 폴더(데스크톱 전용, 네트워크 드라이브 근거 없음). 팀 공유의 공식 경로는 **프로젝트를 조직 또는 그룹에 공유**(지식은 공유, 채팅은 비공개)와 Google Drive, Microsoft 365(SharePoint, OneDrive) 커넥터. https://support.claude.com/en/articles/9519189 (발췌) |

| P3 | 프리필(응답 첫머리 채우기) | 해당 없음 | 덱에 없음. 4.6 이후 400 오류이므로 넣지 말 것 |

## 대본에서 고친 것

1. 라인업은 Haiku 4.5, Sonnet 5, Opus 5, **Fable 5**로 둔다. Fable 5.1은 2026-09-01에 나왔지만 Enterprise 반영이 느려 한 줄로만 언급(발표자 결정). 시간축의 출시와 컷오프는 공식 값과 일치.
2. "파라미터가 많다"를 지능, 속도, 비용 축으로. 파라미터 수는 미공개.
3. "정할 수 있는 건 두 가지"는 유지. 사고 토글은 레거시라 다루지 않음.
4. Haiku 4.5는 Effort가 없다는 한 줄.
5. 토큰 정의를 "단어, 단어 조각, 글자".
6. 컨텍스트 윈도우 100만 토큰. 구성 도식을 순서도가 아니라 구성도로.
7. 지침에 조직 지침 한 줄. 매 메시지에 들어간다로.
8. 메모리를 Topics 항목, 대화 중 갱신, Enterprise 기본 꺼짐, 프로젝트별 분리로.
9. 레이어 표: 지침 매 메시지 / 메모리 대화 중 읽고 갱신 / 프롬프트 매번 / 프로젝트 지식은 작으면 전체, 크면 검색.
10. "넓은 의미로는 다 RAG"는 원문대로 유지. 프로젝트 지식이 작으면 전체 포함, 크면 검색이라는 사실만 레이어 표에 반영.
11. 커넥터 허브를 Google Drive, Gmail, Google Calendar, Slack, GitHub, Microsoft 365로. Office 앱은 애드인으로 각주.
12. 팀 자료를 "프로젝트 공유"와 "드라이브 커넥터" 둘로. File System 삭제.
13. 결과물 절의 논거를 바꿈. 말과 예시는 공식 권장 방법이고, 문제는 매 대화 반복. 스킬은 반복 제거, 필요할 때만 로드, 스크립트와 템플릿으로 재현.
14. 스킬 정의를 "지침과 스크립트와 자료를 묶어 둔 폴더". 폴더 구성에 references/ 반영.
15. 플러그인 정의에 서브에이전트 추가. 채팅에서는 스킬만 동작.
16. 프롬프트 가이드 "의미 없다"를 "전부 황금률 하나로 수렴한다"로. Anthropic의 원칙 그대로.
